# AlgoAgent 部署文档

> **单容器即完整产品**：FastAPI（API + 前端托管）+ Playwright Chromium（沙箱校验）打包在同一镜像，容器内不装 Nginx，单进程单端口。
> 数据全部落在 `/data` 卷（SQLite 数据库 + 生成页面 + 运行时配置），**升级镜像、重启容器均不丢数据**。
>
> **两种部署路径**：
> - **方案 A（推荐）**：任意 Linux 服务器——本地构建镜像后离线传输，**服务器无需外网**
> - 方案 B：服务器现场构建——需要服务器能访问外网拉取依赖

---

## 一、前置要求

### 本地（构建机，方案 A 需要）

- Windows / macOS / Linux 均可，已安装 Docker（Docker Desktop 或 Docker Engine 20.10+）
- 项目源码完整（`backend/` + `frontend/` + `deploy/`）

### 服务器（目标机）

| 项 | 要求 | 验证命令 |
|---|---|---|
| 系统 | 任意 x86_64 Linux（Ubuntu / CentOS / Debian / openEuler 等） | `uname -m` → `x86_64` |
| Docker | 20.10+ | `docker --version` |
| 内存 | ≥ 2GB（沙箱 Chromium 需要，推荐 2C4G） | `free -h` |
| 磁盘 | ≥ 5GB 可用（镜像约 1.5GB + 数据卷） | `df -h /opt` |
| 网络 | 方案 A 无需外网；需开放服务端口（默认 80） | 云厂商安全组 + `firewalld`/`ufw` |
| LLM 端点 | 一个 OpenAI 兼容协议的模型服务（部署后在管理端配置，见第五节） | — |

> **ARM 服务器（鲲鹏等）**：本镜像为 x86_64，ARM 需在本地另行构建 `docker buildx build --platform linux/arm64`，其余流程相同。

## 二、方案 A：任意 Linux 服务器部署（镜像离线传输，推荐）

> 适用：华为云 / 阿里云 / 腾讯云 / 机房自建 / 校园服务器，**只要能 SSH 进去且装了 Docker 即可**。

### 第 1 步：本地构建镜像

```powershell
# Windows（项目根目录）
cd C:\workspace\huaweimadao\pro4
docker build -f deploy/Dockerfile -t algoagent:latest .
```

- 首次约 5-10 分钟（基础镜像国内源已预配：DaoCloud / npmmirror / 华为云 PyPI）
- 已构建过则全部走缓存，秒级完成

### 第 2 步：导出镜像文件

```powershell
docker save -o algoagent.tar algoagent:latest
```

- 生成约 **1.2-1.6GB** 的 `algoagent.tar`（在当前目录）
- 该文件包含完整产品：后端 + 前端 + Chromium 沙箱 + 全部依赖

### 第 3 步：传输到服务器

```powershell
# 方式 1：scp（Windows 自带 OpenSSH，会提示输入服务器密码）
scp .\algoagent.tar root@<服务器IP>:/opt/

# 方式 2：图形工具（scp 断线就得重传时用）
#   WinSCP / FileZilla / 宝塔面板文件管理，上传到 /opt/
#   ※ 传前可先压缩减小体积：tar 文件已是紧凑格式，收益有限，非必需
```

> 大文件传输中断重传即可（scp 不支持断点续传，图形工具多支持）。

### 第 4 步：服务器装载镜像（SSH 到服务器）

```bash
docker load -i /opt/algoagent.tar
docker images | grep algoagent          # 确认出现 algoagent:latest
```

### 第 5 步：配置环境变量

```bash
mkdir -p /opt/algoagent && cd /opt/algoagent

# 生成 SECRET_KEY（必填，用于登录令牌签名）
python3 -c "import secrets; print(secrets.token_urlsafe(32))" 2>/dev/null \
  || openssl rand -base64 32

cat > .env << 'EOF'
SECRET_KEY=粘贴上一步生成的随机串
PUBLIC_BASE_URL=http://<服务器IP>
EOF
```

**环境变量说明**：

| 变量 | 必填 | 说明 |
|---|---|---|
| `SECRET_KEY` | **必填** | 登录令牌签名密钥；缺失时容器启动即退出（安全设计） |
| `PUBLIC_BASE_URL` | 强烈建议 | 分享链接/二维码的对外地址；不设则链接指向 127.0.0.1 不可用 |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 可不配 | 模型在部署后经管理端网页配置（推荐，见第五节）；仅管理员可用此兜底配置 |
| `ALGOAGENT_DATA_DIR` / `ALGOAGENT_PAGES_DIR` | 不动 | 容器内固定 `/data`，已内置默认 |

### 第 6 步：启动

```bash
docker run -d --name algoagent \
  -p 80:8000 \
  -v algoagent_data:/data \
  --env-file /opt/algoagent/.env \
  --restart unless-stopped \
  algoagent:latest
```

参数说明：

| 参数 | 含义 |
|---|---|
| `-p 80:8000` | 宿主机 80 → 容器 8000（**左边可改，右边不可改**，见第六节） |
| `-v algoagent_data:/data` | 数据卷：数据库/作品/配置持久化，删容器不丢数据 |
| `--env-file` | 注入第 5 步的 .env |
| `--restart unless-stopped` | 服务器重启后容器自动拉起 |

### 第 7 步：验证

```bash
curl http://127.0.0.1/api/health        # {"status":"ok"}  ← 服务就绪
docker logs algoagent --tail 20         # 无报错
docker ps | grep algoagent              # STATUS 为 Up
```

## 三、方案 B：服务器现场构建（需外网）

适合服务器能访问外网的场景（如华为云 ECS）：

```bash
# 1. 把整个项目目录传到服务器（git clone 或 scp -r），然后：
cd /path/to/pro4/deploy
cp .env.example .env && vi .env          # 同方案 A 第 5 步：SECRET_KEY + PUBLIC_BASE_URL
cd ..

# 2. 构建 + 启动
docker build -f deploy/Dockerfile -t algoagent:latest .
docker run -d --name algoagent -p 80:8000 -v algoagent_data:/data \
  --env-file deploy/.env --restart unless-stopped algoagent:latest

# 或 compose 一键（自动健康检查）
cd deploy && docker compose up -d --build
```

## 四、部署后首次配置（必做）

### 4.1 注册管理员

浏览器打开 `http://<服务器IP>/` → 注册第一个账号 → **自动成为管理员**。

### 4.2 配置模型（关键步骤）

> **注意**：公网服务器访问不到校园内网模型（如 172.31.2.220）。必须配置一个公网可达的模型端点。

1. 登录管理员 → 右上角头像 → **个人中心 → 管理 → 模型配置**
2. 点 **「＋ 添加内置模型」**，填写：

| 字段 | 示例 | 说明 |
|---|---|---|
| 名称 | DeepSeek 官方 | 对话下拉中显示的名字 |
| 接口地址 | `https://api.deepseek.com/v1` | OpenAI 兼容 base_url（华为云 MaaS / DeepSeek API / 通义等均可） |
| 模型名称 | `deepseek-chat` | 端点对应的模型 ID |
| API Key | `sk-…` | 服务商提供的密钥 |

3. 点 **「测试连接」** → 显示 `✓ 连接成功` 即通
4. 点 **「添加为内置模型」** → 列表出现后点 **「设为默认」**

配置完成后所有用户即可正常生成（普通用户也可在「个人中心 → 模型」添加自己的自定义模型）。

### 4.3 完整验收清单

- [ ] `curl http://127.0.0.1/api/health` 返回 `{"status":"ok"}`
- [ ] 浏览器打开首页出现登录页（前端托管正常）
- [ ] 注册 → 登录 → 发送「生成一个冒泡排序的演示动画」
- [ ] 澄清问答 → 生成完成 → 左侧出现可交互动画（**容器内沙箱校验通过**）
- [ ] 点「分享」→ 二维码/链接在另一设备（手机）可打开
- [ ] 浏览器刷新页面（F5）不 404（SPA 路由正常）
- [ ] `docker logs algoagent` 无持续报错

全部勾选 = 部署成功。

## 五、模型接入体系说明

| 层级 | 谁管理 | 谁可用 | 配置位置 |
|---|---|---|---|
| **内置模型** | 管理员 | 所有用户（对话中可选） | 管理 → 模型配置 → ＋添加内置模型 |
| **默认模型** | 管理员（在内置中标记一个） | 未主动选择模型的请求 | 内置模型行的「设为默认」 |
| **自定义模型** | 每个用户自己 | 仅本人（Key 不外泄） | 个人中心 → 模型 → ＋添加自定义模型 |
| **环境变量兜底** | 部署者（.env） | 仅管理员（公网防滥用） | `.env` 的 LLM_* 三项 |

解析优先级：**对话中选择的模型 > 默认内置标记 > 第一个启用的内置 > 环境变量 > 出厂配置**。

管理员可随时「停用」某内置模型：停用后普通用户不可见不可用，仅管理员保留访问（防公网滥用）。

## 六、端口映射说明

`-p 宿主端口:容器端口` —— **左边可改，右边（8000）不可改**（容器内服务固定监听 8000）：

| 场景 | 启动参数 | 必须同步修改 |
|---|---|---|
| 默认（80） | `-p 80:8000` | — |
| 80 被占用 | `-p 8080:8000` | `.env` 的 `PUBLIC_BASE_URL=http://IP:8080`；防火墙放行 8080 |
| 仅本机调试 | `-p 127.0.0.1:8000:8000` | 同上改 PUBLIC_BASE_URL |
| 换端口后验证 | — | `curl http://127.0.0.1:8080/api/health` |

**时区**：镜像已内置 `TZ=Asia/Shanghai`（会话/消息/作品时间按北京时间显示）。若需其他时区：`docker run -e TZ=Asia/Tokyo ...` 覆盖。

**一句话：左变右不变，变了 PUBLIC_BASE_URL 要跟着变**（否则分享二维码里的地址是错的）。

改端口操作：

```bash
docker rm -f algoagent
docker run -d --name algoagent -p 8080:8000 -v algoagent_data:/data \
  --env-file /opt/algoagent/.env --restart unless-stopped algoagent:latest
# 数据卷保留，账号/作品/分享链接全不丢
```

## 七、日常运维

### 日志

```bash
docker logs algoagent --tail 100        # 最近 100 行
docker logs -f algoagent                # 实时跟踪（生成过程含逐轮进度日志）
```

### 升级（数据不丢）

```bash
# 本地：重建镜像 → 导出 → 传输（同方案 A 第 1-3 步）
# 服务器：
docker load -i /opt/algoagent.tar

  --env-file /opt/algoagent/.env --restart unless-stopped algoagent:latest

```

### 备份 / 恢复

```bash
# 备份（数据卷打包）
docker run --rm -v algoagent_data:/data -v $(pwd):/backup alpine \
  tar czf /backup/algoagent-data-$(date +%F).tar.gz -C /data .

# 恢复
docker volume create algoagent_data
docker run --rm -v algoagent_data:/data -v $(pwd):/backup alpine \
  sh -c "cd /data && tar xzf /backup/algoagent-data-<日期>.tar.gz"
```

### 停止 / 重启

```bash
docker stop algoagent     # 停止（数据保留）
docker start algoagent    # 再次启动
docker rm -f algoagent    # 删除容器（数据在卷中，仍保留；配合 volume rm 才会彻底删除数据）
```

## 八、TLS / HTTPS（可选）

容器只跑 HTTP。需要 HTTPS 时：

1. **云厂商负载均衡**（推荐，华为云 ELB）：ELB 终结 TLS → 转发到 ECS:80，容器零改动
2. **自建 Nginx 反代**：`proxy_pass http://127.0.0.1:80;` + SSL 证书（标准配置）

开启 HTTPS 后记得把 `PUBLIC_BASE_URL` 改为 `https://你的域名` 并重启容器。

## 九、常见问题排查

| 现象 | 原因与解决 |
|---|---|
| 容器启动即退出 | `docker logs algoagent` 看报错：提示 SECRET_KEY → .env 没注入（检查 `--env-file` 路径）或值为空 |
| curl health 不通 | 容器没起来（`docker ps` 看 STATUS）或端口映射错（`docker port algoagent` 核对） |
| 浏览器打不开首页 | 云安全组 / firewalld 未放行端口；`curl 127.0.0.1` 通而外网不通 = 防火墙问题 |
| 「暂无可用模型」提示 | 未配置任何模型 → 管理员按第 4.2 节添加内置模型并设默认 |
| 模型测试连接失败 | 端点地址/Key 错误，或端点不可达（公网服务器访问不到内网地址属正常——换公网端点） |
| 生成一直卡在"沙箱校验" | 服务器内存不足（Chromium 需约 1GB）→ 升配或 `free -h` 检查 |
| 分享链接打不开/地址是 127.0.0.1 | `PUBLIC_BASE_URL` 未设置或端口不对 → 改 .env 后 `docker rm -f` 重 run |
| 刷新页面 404 | 端口变了但用了旧链接；或经反向代理未转发路由 → 确认访问的是 run 映射的端口 |
| scp 传输太慢 | 改用图形工具（WinSCP 等）夜间传输；或先传网盘再服务器 wget（需外网） |
| docker load 报错 tar 损坏 | 传输中断 → 校验文件大小（本地与服务器 `ls -l` 对比）后重传 |

## 十、架构说明（为什么是单镜像）

```
┌─────────────────── docker 容器 :8000 ───────────────────┐
│  uvicorn 单进程                                          │
│  ├── FastAPI：/api/* 业务接口 + /s/{token} 分享页        │
│  ├── StaticFiles：前端 dist（SPA 路由后端 fallback）     │
│  └── 沙箱校验：独立子进程跑 Playwright Chromium          │
│         （生成页文件挂载自 /data 卷）                    │
└──────────────────────────┬──────────────────────────────┘
                     /data 卷（持久化）
                     ├── SQLite（用户/会话/作品/分享/模型）
                     ├── pages/（生成的算法动画 HTML）
                     └── 运行时配置
```

- 无 Nginx：前端产物由 FastAPI 直接托管，SPA 刷新路由由后端兜底
- 沙箱隔离：校验在子进程运行，页面崩溃不影响主服务
- 数据与镜像分离：升级/重启/换机（数据卷迁移）均不影响用户数据与已分享链接
